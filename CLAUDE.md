## Workflow Rules

These are Blu's standing rules. Follow them on every task in this repo.

1. **Commit message after every chunk of work.** Hand over a paste-ready commit message in Blu's voice: casual, punchy, like she's talking to herself. No attribution lines. No `Co-Authored-By`, no `Claude-Session`, nothing like that.
2. **PR message when a ticket is done.** When a Jira, GitHub, or Gitea ticket or issue is finished, deliver a PR summary/message in Blu's voice. Same rule: no attribution lines.
3. **Docs after every chunk.** Update every doc the work touches, add a new file in `/docs` if the work earns one, and update the README.
4. **Never commit, never branch.** Do not run `git commit` and do not create branches. Stage only, then hand Blu the commit message.
5. **Comments sound like Blu.** Write code comments like Blu talking to herself, not like a developer writing documentation.
